## 1. What C_TradeSkillUI, C_CraftingOrders, C_ProfSpecs, C_AuctionHouse, C_Item/ItemLocation and C_Bank expose for crafting

### Takeaway
Retail exposes a very rich, mostly unrestricted read API for crafting. Through `C_TradeSkillUI`, an addon can get full recipe schematics (reagent slots, required quantities, optional/finishing slots), operation info (skill vs. difficulty, quality thresholds, concentration cost, ingenuity refund, bonus stats), quality item IDs and recraft data. Crafting orders can be listed, claimed, fulfilled, rejected and placed. Profession specialization trees are readable through `C_ProfSpecs`. The AH supports separate commodity and item search flows plus a full-AH `ReplicateItems` scan. `C_Item.GetItemCount` can include bank, reagent bank and warband (account) bank counts. The main catch is that most profession data is only available while the profession window or data source is open on the current character.

### Inferences
- An addon can reproduce most of Blizzard's crafting math client-side (CraftSim-style quality/concentration simulation) because skill, difficulty, thresholds, concentration cost and bonus stats are all exposed.
- Warband bank stock can be counted for materials-on-hand features without opening the bank, via `GetItemCount(..., includeAccountBank=true)`. Exact per-slot contents still need the bank to have been opened and cached (inference; not verified).
- The listing does not include a C_AuctionHouse function that queries prices without the AH open. Price features therefore need an AH-open scan cache (Auctionator/TSM pattern) or external data.

## 2. Protected and hardware-event-restricted actions, and what they mean for automation and queues

### Takeaway
State-changing economic actions are flagged `HasRestrictions` in Blizzard's docs. In practice that means they need a hardware event (a real click or keypress) and cannot be fired from timers or loops: `ClaimOrder`, `PlaceNewOrder`, `PostItem`, `PostCommodity`, `ConfirmPostItem`, `ConfirmPostCommodity`, `StartCommoditiesPurchase`, `PlaceBid`, `CancelAuction` and `PurchaseBankTab`. `CraftRecipe` and `FulfillOrder` are *not* flagged, yet mainstream queue addons still bind them to a user click (one click, one craft or batch). A crafting addon can prepare, rank and stage everything, but every claim, post, buy and craft should be driven by a user click.

### Cited Findings
- `HasRestrictions = true` appears only on these crafting/AH/bank functions: `C_CraftingOrders.ClaimOrder`, `C_CraftingOrders.PlaceNewOrder`; `C_AuctionHouse.CancelAuction`, `ConfirmPostCommodity`, `ConfirmPostItem`, `PlaceBid`, `PostCommodity`, `PostItem`, `StartCommoditiesPurchase`; `C_Bank.PurchaseBankTab` — [DOC/CraftingOrderUIDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/CraftingOrderUIDocumentation.lua), [DOC/AuctionHouseDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/AuctionHouseDocumentation.lua), [DOC/BankDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/BankDocumentation.lua)
- Not flagged: `C_TradeSkillUI.CraftRecipe/CraftEnchant/CraftSalvage/RecraftRecipe/RecraftRecipeForOrder`, `C_CraftingOrders.FulfillOrder/RejectOrder/ReleaseOrder/CancelOrder`, `C_AuctionHouse.ConfirmCommoditiesPurchase`, and all search/query functions — same doc files. (A flag's absence does not prove the function is unrestricted at runtime; see Gaps.)
- C_RestrictedActions provides `CheckAllowProtectedFunctions(object, silent)` ("Returns true if the calling context has permissions to call protected functions on the supplied object"), `InCombatLockdown()`, and the events `ADDON_ACTION_BLOCKED` / `ADDON_ACTION_FORBIDDEN` (payload: isTainted, function) and `MACRO_ACTION_BLOCKED` — [DOC/RestrictedActionsDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/RestrictedActionsDocumentation.lua)
- CraftSim's craft queue calls craft from a button handler guarded by `CraftSim.CRAFTQ:BeginCraftClickLock()`, crafting 1 at a time (`fresh:Craft(1)`) — [CraftSim Modules/CraftQueue/UI.lua](https://github.com/derfloh205/CraftSim/blob/main/Modules/CraftQueue/UI.lua). It also uses `hooksecurefunc(C_TradeSkillUI, "CraftRecipe", ...)` to observe crafts started by any source — [CraftSim Init/Init.lua](https://github.com/derfloh205/CraftSim/blob/main/Init/Init.lua)
- Addon authors report that opening the Professions frame is hardware-event protected (it won't open from addon code without a real key or click). The ProfessionDataInitializer library works around this by having the user press a key and waits until out of combat. This is a search-snippet summary of its CurseForge page; the page itself could not be fetched — [CurseForge: ProfessionDataInitializer](https://www.curseforge.com/wow/addons/professiondatainitializer)
- Hooking `CraftRecipe` via `hooksecurefunc` is a common pattern for detecting craft starts; one user reported the hooked count always reading 1 for some professions — search-snippet summary of [Blizzard forums: CraftRecipe always returning numCasts = 1](https://us.forums.blizzard.com/en/wow/t/ctradeskilluicraftrecipe-always-returning-numcasts-1/1447442)

### Inferences
- **Feasible:** a craft queue with a "Craft next" button (one click per step); a "claim best order" button (one click per claim); AH "post next" or "buy next" buttons (the TSM/Auctionator model); auto-filling reagent and concentration choices before the click; restock calculations.
- **Not feasible:** unattended mass crafting, automatic order sniping or claiming on a timer, automatic AH posting/buying/cancel-scanning loops, or a single click that triggers a chain of several restricted calls (each restricted call generally needs its own hardware event; inference based on standard WoW hwevent semantics).
- Commodity purchase is two steps: `StartCommoditiesPurchase` (restricted) then `ConfirmCommoditiesPurchase` once the price quote arrives. The UX should expect a quote/confirm round-trip (`COMMODITY_PRICE_UPDATED`, `GetQuoteDurationRemaining`).
- Combat lockdown and Midnight restriction states (see Q3) can block protected/secure frame operations, so queue buttons that use secure templates should be built and changed out of combat.

### Gaps
- Could not confirm from a primary source whether `CraftRecipe` requires a hardware event at runtime (the docs don't flag it; the wiki page [API:C_TradeSkillUI.CraftRecipe](https://warcraft.wiki.gg/wiki/API:C_TradeSkillUI.CraftRecipe) was unreachable). Treat it as "must be user-click-driven" to be safe.
- Exact semantics of `HasRestrictions` (hwevent vs. protected vs. secure-only) are not documented in the generated files.

## 3. Midnight (12.0) addon restrictions (secret values, combat lockdown, "disarmament") and their effect on crafting and AH addons

### Takeaway
Midnight added "secret values" (opaque values that tainted addon code can store and pass along but cannot compute with), a new restriction-state system (Combat, Encounter, ChallengeMode, PvPMatch, Map, Chat), the removal of `COMBAT_LOG_EVENT_UNFILTERED`, and a block on addon comms and chat while in instances. Blizzard's own docs show **no secret-value flags on any TradeSkill, CraftingOrder, ProfSpecs, AuctionHouse, Bank or Item function**. Crafting and AH addons are therefore essentially unaffected, except for addon communications during the restricted "Chat" state.

### Cited Findings
- Restriction types (`Enum.AddOnRestrictionType`): Combat ("The player is actively affecting combat"), Encounter ("actively participating in an instance encounter"), ChallengeMode ("active and incomplete challenge mode or mythic keystone dungeon"), PvPMatch, Map ("on a map that applies addon restrictions"), Chat ("in a state where addon chat communications are restricted") — [DOC/RestrictedActionsConstantsDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/RestrictedActionsConstantsDocumentation.lua)
- New APIs: `C_RestrictedActions.GetAddOnRestrictionState(type)` and `IsAddOnRestrictionActive(type)`, plus the event `ADDON_RESTRICTION_STATE_CHANGED` ("always fired before a restriction becomes active, or after it is deactivated") — [DOC/RestrictedActionsDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/RestrictedActionsDocumentation.lua)
- Secret-value flags (`SecretInChatMessagingLockdown`) appear only in ChatInfo and GuildInfo docs. TradeSkillUI, CraftingOrderUI, ProfessionSpecUI, AuctionHouse, Bank and Item functions carry only `SecretArguments = "AllowedWhenUntainted"` (an argument-handling rule) or no flag at all. Result of my parsing of the doc files listed above, e.g. [DOC/GuildInfoDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/GuildInfoDocumentation.lua)
- `C_ChatInfo.SendAddonMessage` and `SendAddonMessageLogged` are `SecretArguments = "NotAllowed"`. `Enum.SendAddonMessageResult` gained `AddOnMessageLockdown` (11) and `TargetOffline` (12). New `C_ChatInfo.AreOutgoingAddonChatMessagesRestricted()`: "Returns false if addons are allowed to send outgoing chat messages. This is controlled on a realm-by-realm basis (tournament realms allow it), and the ability for addons to receive comms is controlled separately." — [DOC/ChatInfoDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/ChatInfoDocumentation.lua), [DOC/ChatConstantsDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/ChatConstantsDocumentation.lua)
- Secret-value rules: tainted code may store secret values and pass them to functions, but may not concatenate them, do arithmetic on them or index them; `issecretvalue` detects them; combat APIs such as `UnitHealth` may return secrets. "While in an instance, chat messages will be sent to Lua as Secret Values, and addons are not allowed to send communications to other players (either through addon comms or regular chat)." — search-snippet summary of [Warcraft Wiki: Patch 12.0.0/Planned API changes](https://warcraft.wiki.gg/wiki/Patch_12.0.0/Planned_API_changes) and [Patch 12.0.0/API changes](https://warcraft.wiki.gg/wiki/Patch_12.0.0/API_changes) (pages not directly fetchable)
- 12.0.5 notes say "relying on Secret Values alone was not going to be enough to prevent addon automation involving auras", and "The secret value system is entirely disabled on Classic builds" — search-snippet summary of [Warcraft Wiki: Patch 12.0.5/API changes](https://warcraft.wiki.gg/wiki/Patch_12.0.5/API_changes)
- `COMBAT_LOG_EVENT_UNFILTERED` was removed (combat addons had to be rewritten) — [Cell releases (GitHub)](https://github.com/jdtoppin/Cell/releases)
- `C_EncodingUtil` (new native `SerializeJSON/CBOR`, `CompressString`, `EncodeBase64`) is useful for compact sync and export payloads — [DOC/EncodingUtilDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/EncodingUtilDocumentation.lua)
- Secondary sites say AH addons (Auctionator) and CraftSim keep working in Midnight and that the restrictions target in-instance combat tooling — [mythic-store.com](https://mythic-store.com/blog/best-wow-midnight-addons-what-still-works-after-the-api-overhaul), [boosting-ground.com](https://boosting-ground.com/wow-boosting/news/wow-midnight-addon-changes) (low-authority commercial sites; consistent with the doc evidence). The CraftSim CurseForge listing claims Midnight (12.x) compatibility — [CurseForge: CraftSim](https://www.curseforge.com/wow/addons/craftsimulator) (search snippet)
- Blizzard reportedly confirmed via the WoW UI Discord that Midnight's addon restrictions also apply to the "WoW Forever" client — [Warperia](https://warperia.com/wow-forever-inherits-midnights-addon-changes/) (secondary; unverified)

### Inferences
- A crafting addon will rarely hit these restrictions, because crafting happens in cities or housing, out of combat and outside instances. Edge cases: a guild-sync or "who can craft X" broadcast sent while the user is in a dungeon or raid will fail with `AddOnMessageLockdown`, and incoming chat-based order requests (e.g. "LF crafter" whisper/trade-chat parsing) can arrive as secret values inside instances. Good practice: check `C_RestrictedActions.IsAddOnRestrictionActive(Enum.AddOnRestrictionType.Chat)` and queue messages until `ADDON_RESTRICTION_STATE_CHANGED`.
- Guild roster/recipe APIs carrying `SecretInChatMessagingLockdown` suggests some guild-member data is hidden during chat lockdown (inference; I did not check which functions specifically).

### Gaps
- No Blizzard blue post was found that explicitly says profession or AH addons are out of scope. The conclusion rests on the doc flags plus secondary sites.
- I could not read the full 12.0.0/12.0.5/12.0.7/12.1 API-change pages, so there is no list of removed or renamed profession functions per patch.

## 4. Reading other players' profession data, and cross-realm/communication limits

### Takeaway
Ways to read other players' profession data: guild-member recipe queries (`C_GuildInfo.QueryGuildMemberRecipes`, `QueryGuildMembersForRecipe`), the guild roster tradeskill view, viewing a linked profession (opens a read-only data source), and custom addon-to-addon sync. Addon comms are throttled per prefix: a 10-message burst, regenerating 1 per second, with 255-character messages and 16-character prefixes. They are blocked in the "Chat" restriction state (in instances).

### Cited Findings
- `C_GuildInfo.QueryGuildMemberRecipes(guildMemberGUID, skillLineID)`, `C_GuildInfo.QueryGuildMembersForRecipe(skillLineID, recipeSpellID, recipeLevel)`; events `GUILD_TRADESKILL_UPDATE`, `GUILD_RECIPE_KNOWN_BY_MEMBERS` — [DOC/GuildInfoDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/GuildInfoDocumentation.lua)
- `C_TradeSkillUI.IsGuildTradeSkillsEnabled()` and data-source events `TRADE_SKILL_DATA_SOURCE_CHANGING/CHANGED` (the profession UI can show another player's linked or guild profession) — [DOC/TradeSkillUIDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/TradeSkillUIDocumentation.lua)
- `C_ChatInfo.RegisterAddonMessagePrefix`, `SendAddonMessage(prefix, message, chatType, target)`, `SendAddonMessageLogged` ("Intended for plain text payloads; logged and throttled"), events `CHAT_MSG_ADDON`, `CHAT_MSG_ADDON_LOGGED`, `BN_CHAT_MSG_ADDON`; result codes include `AddonMessageThrottle`, `ChannelThrottle`, `NotInGroup`, `NotInGuild`, `TargetRequired`, `AddOnMessageLockdown`, `TargetOffline` — [DOC/ChatInfoDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/ChatInfoDocumentation.lua), [DOC/ChatConstantsDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/ChatConstantsDocumentation.lua)
- Throttle: each registered prefix starts with an allowance of 10 messages, regains 1 per second up to 10, and the server "can dynamically reconfigure" these defaults. Message ≤255 characters, prefix ≤16 characters — search-snippet summary of [Warcraft Wiki: API C_ChatInfo.SendAddonMessage](https://warcraft.wiki.gg/wiki/API_C_ChatInfo.SendAddonMessage); the 255 cap also appears at [wowprogramming.com](https://wowprogramming.com/docs/api/SendAddonMessage.html) and a [WoWInterface thread](https://wowinterface.com/forums/showthread.php?p=328476)
- ChatThrottleLib (bundled with Ace3's AceComm) does traffic shaping on top of the server throttle — [Warcraft Wiki: ChatThrottleLib](https://warcraft.wiki.gg/wiki/ChatThrottleLib) (search snippet)

### Inferences
- A guild "who can craft this" feature is feasible through the native guild recipe query (no peer addon needed). Quality, specialization and concentration details for other players are not exposed by these queries (inference based on their signatures), so a richer crafter directory (CraftScan-style) needs peer-to-peer sync where both sides run the addon.
- Cross-realm: addon whispers and party/raid/guild channels work for connected/cross-realm group members; Battle.net addon messages (`BN_CHAT_MSG_ADDON`, via `BNSendGameData`) can reach friends across realms. Details were not verified this session.
- Large data (full recipe lists) must be chunked and compressed (`C_EncodingUtil.CompressString` + Base64, or LibDeflate) and paced under the 1 msg/s per-prefix regen.

### Gaps
- Could not verify `BNSendGameData` limits, `CHANNEL`-type addon messaging rules, or whether `QueryGuildMemberRecipes` works for offline members.

## 5. Accessing other characters' data while offline: alt tracking

### Takeaway
The client API returns data only for the logged-in character (plus account-wide data such as the warband bank). Alt tracking therefore means persisting each character's profession, recipe, concentration and inventory snapshot to account-wide SavedVariables when that character logs in or opens its profession window, and reading the snapshots back later.

### Cited Findings
- `C_TradeSkillUI` functions operate on the currently open or initialized profession data source (`OpenTradeSkill`, `TRADE_SKILL_DATA_SOURCE_CHANGED`, `TRADE_SKILL_LIST_UPDATE`). No function takes a character identifier — [DOC/TradeSkillUIDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/TradeSkillUIDocumentation.lua)
- The Professions frame cannot be opened by addon code without a hardware event, so data-gathering libraries prompt the user for a keypress (search snippet) — [CurseForge: ProfessionDataInitializer](https://www.curseforge.com/wow/addons/professiondatainitializer)
- Account-wide warband bank counts are queryable from any character via `C_Item.GetItemCount(..., includeAccountBank)`; personal bank/reagent bank counts only cover the current character — [DOC/ItemDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/ItemDocumentation.lua)
- Concentration is a per-profession currency that regenerates over time (`GetConcentrationCurrencyID(skillLineID)`) — [DOC/TradeSkillUIDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/TradeSkillUIDocumentation.lua). The regen rate is reported as about 1 point per 6 minutes / 10 per hour, cap 1000 — [Icy Veins professions guide](https://icy-veins.com/wow/professions) (search snippet; secondary)

### Inferences
- Alt features must be snapshot-based: record a timestamp and value on logout or profession open, then extrapolate regenerating resources (concentration, cooldowns) offline from the regen rate. Data stays stale until the alt logs in and opens each profession. The Blizzard web API (Q6) can fill some gaps (e.g. which professions and recipes a character knows) without logging in, but it needs an external tool, not the in-game addon.
- SavedVariables are written only on logout or `/reload`, and only for the local WoW install. Multi-PC or companion-app sync needs an external app reading the SavedVariables files (the TSM Desktop App pattern).

### Gaps
- Did not verify whether any 12.x API exposes account-wide (warband) profession/knowledge data across characters.

## 6. External tools: Blizzard Battle.net Web API (profession, recipe, auction/commodity endpoints) and limits

### Takeaway
External tools use the Battle.net Game Data API (OAuth client credentials). Connected-realm auctions cover non-commodity items. A separate region-wide commodities endpoint (since 9.2.7) updates hourly. Profession and recipe reference endpoints and character-profile profession endpoints also exist. The commonly cited rate limit is 36,000 requests/hour and 100/second (429 on overflow), but I found it only on third-party listings.

### Cited Findings
- Since patch 9.2.7, "non-commodity auction data will continue to be exposed for each connected-realm on the existing auction endpoints", while "the commodities endpoint will report all regional auction data for the targeted namespace (e.g. dynamic-us) updating every hour" — search-snippet summary of [Blizzard forums: Immediate change to Auction APIs for Commodities with 9.2.7](https://us.forums.blizzard.com/en/blizzard/t/immediate-change-to-auction-apis-for-commodities-with-927/31522)
- Using `If-Modified-Since` on the commodities endpoint still incurs the full request cost (developer report) — search-snippet summary of [Blizzard forums: Auctions API missing commodities data](https://us.forums.blizzard.com/en/blizzard/t/auctions-api-missing-commodities-data/31497)
- Rate limit of 36,000 requests per hour at up to 100 requests per second, with 429 on the per-second limit — [publicapis.dev listing](https://publicapis.dev/resource/battle-net/mfqhkelj) (third-party; not verified on develop.battle.net)
- Developers have reported sudden 429s across Game Data endpoints — [Blizzard forums: All Game Data Endpoints -- 429 Errors](https://us.forums.blizzard.com/en/blizzard/t/all-game-data-endpoints-429-errors/52486)
- Classic Anniversary realms also have an auction API, though connected-realm lookup has caused trouble — [Blizzard forums: TBC Classic Anniversary Thunderstrike auction API](https://us.forums.blizzard.com/en/blizzard/t/tbc-classic-anniversary-thunderstrike-auction-api/58703)
- Community wrappers expose "all commodities data for the region" and per-connected-realm auctions — [get-wow-data (PyPI)](https://pypi.org/project/get-wow-data/)

### Inferences
- Commodity prices (most crafting reagents and consumables) are region-wide and hourly. A web or companion tool can compute crafting profitability for reagents and consumables without in-game scans, but crafted gear (non-commodity) needs per-connected-realm data.
- Hourly snapshots cannot give real-time sniping data. The in-game AH scan (`ReplicateItems`, commodity search) remains the source of live prices.

### Gaps
- Could not reach develop.battle.net to confirm current endpoint paths (`/data/wow/auctions/commodities`, `/data/wow/profession/{id}`, `/data/wow/recipe/{id}`, `/profile/wow/character/{realm}/{name}/professions`), current rate limits, or whether recipe endpoints expose Midnight quality/concentration data. These paths come from prior knowledge and are unverified.

## 7. Libraries and reference addons for crafting addon development; Classic differences

### Takeaway
The de facto references are CraftSim (crafting simulation, queue, order handling, open source on GitHub), Auctionator and TSM (AH scanning and posting), and CraftScan (order and crafter-request detection). Standard building blocks are Ace3 (AceAddon/AceDB/AceComm/AceSerializer), ChatThrottleLib, LibDataBroker/LibDBIcon, LibDeflate/LibSerialize, and now native `C_EncodingUtil`. Classic clients use the older, narrower tradeskill API and have no crafting orders, no quality/concentration system and no secret values.

### Cited Findings
- CraftSim source (GitHub `derfloh205/CraftSim`): hooks `C_TradeSkillUI.CraftRecipe`, has a CraftQueue module with click-lock crafting, a CraftLog, crafting-order handling, and a published custom event API (`CRAFTSIM_CRAFT_RECIPE_DATA_PREPARED`, etc.) that other addons can consume — [CraftSim Util/Events.lua](https://github.com/derfloh205/CraftSim/blob/main/Util/Events.lua), [CraftSim Modules/CraftQueue/CraftQueue.lua](https://github.com/derfloh205/CraftSim/blob/main/Modules/CraftQueue/CraftQueue.lua)
- The CraftSim CurseForge page lists Midnight (12.x) compatibility and concentration support (quality +1, capped at max) — [CurseForge: CraftSim](https://www.curseforge.com/wow/addons/craftsimulator) (search snippet)
- Enhanced Crafting is a newer Midnight (12.0.x) addon that adds a quality preview and a reagent "Unlock All" simulation, described as a best-effort estimate — [CurseForge: Enhanced Crafting](https://www.curseforge.com/wow/addons/enhancedcrafting) (search snippet)
- ChatThrottleLib documentation — [Warcraft Wiki: ChatThrottleLib](https://warcraft.wiki.gg/wiki/ChatThrottleLib) (search snippet)
- The native `C_EncodingUtil` serialization/compression API is available in the live client — [DOC/EncodingUtilDocumentation.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/EncodingUtilDocumentation.lua)
- Classic: "The secret value system is entirely disabled on Classic builds" — search-snippet summary of [Warcraft Wiki: Patch 12.0.5/API changes](https://warcraft.wiki.gg/wiki/Patch_12.0.5/API_changes)
- Community tooling for Midnight migration: [DennysOliveira/wow-addon-dev](https://github.com/DennysOliveira/wow-addon-dev) (secret values / API migration templates); an emulator issue on emulating 12.x secret values — [wow-vscode-emulator issue #8](https://github.com/AlexanderYW/wow-vscode-emulator/issues/8)

### Inferences
- CraftSim's open-source code is the best practical reference for the real-world usage of `GetCraftingOperationInfo`, the reagent-slot schematics and order crafting. A new addon could integrate with CraftSim through its events rather than duplicating its simulation.
- Classic (Era/Anniversary/MoP Classic) addons historically use `GetTradeSkillInfo`/`GetNumTradeSkills`/`DoTradeSkill`-style APIs (Era) or older `C_TradeSkillUI` variants. A cross-flavor crafting addon needs a separate code path. This comes from prior knowledge; I did not verify it this session.

### Gaps
- I could not verify the existence, maintenance status or contents of "LibCraftingData" or "LibItemUpgradeInfo" for Midnight (curseforge/wiki blocked). Auctionator and CraftScan sources were not inspected this session. TSM's current state (the TSM Desktop App and its data sources) was not researched.
- Classic API differences were not verified against Classic generated docs (the Gethe repo has `classic`/`classic_era` branches that could be checked in a follow-up).
