# FabricationStation — Design Spec

Date: 2026-10-30
Status: Draft for review
Background research: `reports/WoW crafting addon landscape.md` and `research_notes/WoW crafting addon landscape/`

## 1. Purpose

FabricationStation is an all-in-one crafting addon for World of Warcraft retail — "Warband Nexus, but for crafting". It replaces the stack crafters run today (CraftSim + order helpers + knowledge trackers + alt trackers) with one addon, built around a single account-wide view of every character's crafting.

- **Primary user:** the author, a multi-alt crafter who uses Auctionator.
- **Later users:** public release on CurseForge/Wago once the personal version is solid.
- **Success looks like:** the author uninstalls CraftSim and their order/knowledge/alt helpers and runs FabricationStation + Auctionator only, without losing capability, and with better order and customer handling than any current addon.

## 2. Decisions already made

| Decision | Choice |
|---|---|
| Game version | Retail only (Midnight 12.x). Classic out of scope. |
| Relationship to CraftSim | **Replace it.** FabricationStation owns its own quality / concentration / reagent math. |
| Price source | **Auctionator** (required dependency) plus manual overrides. No TSM dependency. |
| Build order | Phase 1 crafting math + profit + queue → Phase 2 orders, customers, ledger → Phase 3 alts + planner → Phase 4 public/social. |
| Code structure | One addon, internal modules with defined interfaces, Ace3 libraries, crafting math in pure Lua testable outside the game. |
| Name | FabricationStation (slash command `/fs`, alias `/fabstation`). |
| Scope boundary | In-game only. No companion app or website. |

## 3. Design rules

1. **Works on its own.** The main window works anywhere, on any character, from saved data — browsing profit, recipes, queue, orders, customers, and alts never requires a profession window to be open.
2. **Works alongside Blizzard's UI.** FabricationStation never replaces, hides, or reparents Blizzard's Professions or Crafting Orders frames. Its panels dock beside them; every Blizzard button keeps working. Disabling the addon leaves default UI untouched.
3. **Every protected action is a player click.** Crafting, claiming orders, and buying happen only from a button the player clicks. No loops, no timers, no unattended actions.
4. **Math never calls the game.** The Math module is pure Lua with no WoW globals, so it is fully unit-testable.
5. **Only the Prices module talks to Auctionator.**
6. **Show uncertainty, never hide it.** Missing prices, stale prices, stale character data, and math mismatches are visible in the UI.
7. **No taint.** Only own frames and `hooksecurefunc`-style post-hooks on Blizzard code; never write to Blizzard frame fields or call protected functions from insecure code paths outside a click.

## 4. Architecture

### 4.1 Modules

| Module | Responsibility | Depends on | Phase |
|---|---|---|---|
| **Core** | AceAddon bootstrap, AceDB SavedVariables (account-wide with per-character sections), settings (AceConfig), internal message bus (AceEvent messages / CallbackHandler), schema versioning + migrations, module enable/disable and failure isolation. | Ace3 | 1 |
| **Scanner** | Reads game state and writes snapshots to the DB: professions, skill, known recipes, recipe schematics, specialization state, concentration, Moxie, cooldowns, tools/gear, item counts (bags, bank, reagent bank, warband bank). | Core, WoW API | 1 |
| **GameData** | Static tables shipped with the addon for data the live API does not expose in a usable form (e.g. spec node effects, finishing/optional reagent effects, concentration curve constants, recipe sources, knowledge sources). Generated by an offline script; stamped with game build. | — | 1 (grows in 3) |
| **Prices** | Single price interface: `Prices:Get(itemID) → {value, source, ageDays}`. Order: manual override → Auctionator AH price → Auctionator vendor price → `nil` ("no price"). Never returns 0 for unknown. | Core, Auctionator API | 1 |
| **Math** | Pure Lua. Skill/quality prediction, concentration cost, Multicraft/Resourcefulness/Ingenuity expected values, reagent optimizer, expected profit, gold per concentration point. Inputs are plain tables; outputs are plain tables. | GameData (passed in) | 1 |
| **Recipes** | Joins Scanner data + Prices + Math into per-recipe, per-character results; runs the chunked recipe scan; caches results and invalidates on price/inventory/skill change. | Scanner, Prices, Math | 1 |
| **Queue** | Craft list with quantity and assigned character; restock targets; missing-reagent calculation; Auctionator shopping-list export; Craft Next. | Recipes, Prices, Scanner | 1 |
| **Orders** | Reads crafting orders, scores them, flags risk, filters, keeps a saved snapshot of the last board seen, Claim Best Order. | Recipes, Prices | 2 |
| **Customers** | Customer records captured on order fulfilment, notes/tags, alt linking, search, export, highlight/warn in Blizzard's order list. | Orders, Core | 2 |
| **Ledger** | Income/expense records: order commissions, AH sales from mail, craft cost basis; weekly/per-recipe profit; personal commission benchmarks. | Orders, Customers, Prices | 2 |
| **Alts** | Full per-character profession overview; account-wide reagent location; weekly knowledge state. | Scanner, GameData | 3 (minimal slice in 1) |
| **Planner** | Weekly knowledge checklist, concentration scheduler and cap warnings, specialization advice, missing-recipe finder. | Alts, Recipes, GameData | 3 |
| **UI** | Main window, profession side panel, crafting-orders additions, tooltips, minimap/LDB launcher. One sub-module per surface. | All above via their public functions | 1→3 |
| **Guild / ChatScan / Onboarding** | Guild crafter directory (addon sync + native guild recipe query fallback), trade-chat request scanner, first-run setup wizard. | Core, Recipes | 4 |

### 4.2 Data flow

```
Game event ─▶ Scanner ─▶ DB snapshot ─▶ message "FS_DATA_CHANGED"
                                             │
Auctionator DB update ─▶ Prices ─▶ message "FS_PRICES_CHANGED"
                                             ▼
                              Recipes (Math + Prices + snapshot, cached)
                                             ▼
                                   UI / Queue / Orders / Planner
```

Modules communicate only through public functions and bus messages. No module reads another module's private tables.

### 4.3 Saved data (AceDB)

```
FabricationStationDB = {
  schemaVersion = N,
  global = {
    settings, priceOverrides,
    queue = { entries = { {recipeID, quantity, charKey, targetQuality, useConcentration} } , restock = { [itemID] = target } },
    customers = { [nameRealm] = {orders = {...}, tips, notes, tags, linkedTo} },
    ledger = { entries = { {time, type, itemID, amount, charKey, ref} } },
    ordersSnapshot = { time, orders = {...} },  -- phase 7: replaced by orderBoards[charKey] (migration 3)
    diagnostics = { mismatches = {...} },
    captures = { ... },  -- /fs capture fixtures
  },
  characters = {
    ["Name-Realm"] = {
      lastSeen, class, gold,
      professions = { [skillLineID] = { skill, maxSkill, recipes = {[recipeID]=true}, spec = {...},
                      concentration = {value, max, time}, moxie, cooldowns = {...}, tools = {...} } },
      items = { [itemID] = {bags, bank, reagentBank} },
      knowledgeWeekly = { ... },
    },
  },
  warband = { items = { [itemID] = count }, time },
}
```

Every snapshot carries a timestamp so the UI can show "data from <time> on this character". Concentration and cooldowns are projected forward from their snapshot time.

### 4.4 WoW API surface (to verify against Blizzard's generated docs on the `live` branch of Gethe/wow-ui-source during planning)

- Professions: `C_TradeSkillUI` (recipe IDs/info, `GetRecipeSchematic`, `GetCraftingOperationInfo`, `CraftRecipe`, concentration currency lookup), `C_ProfSpecs`, `C_CurrencyInfo`.
- Orders: `C_CraftingOrders` (request/list crafter orders, claim, fulfil, release; order info incl. customer name, tip, reagents, minimum quality, rewards).
- Items: `C_Item.GetItemCount` (incl. warband bank), `C_Container`, bank/warband bank events.
- Restricted (click-only): `ClaimOrder`, `PlaceNewOrder`, AH post/purchase/cancel functions. `CraftRecipe` is not flagged but is treated as click-only.
- Midnight secret-value restrictions do not cover profession, order, AH, or item APIs. Addon messages are blocked in instances (relevant to Phase 4 guild sync only).

### 4.5 Auctionator integration (to verify against Auctionator's `Source/API/v1`)

- `Auctionator.API.v1.GetAuctionPriceByItemID / ByItemLink` — AH price (quality ranks have separate item IDs).
- `Auctionator.API.v1.GetVendorPriceByItemID` — vendor price.
- `Auctionator.API.v1.GetAuctionAgeByItemID` (if present) — price age in days.
- `Auctionator.API.v1.CreateShoppingList` + `ConvertToSearchString` — shopping list export with exact items and quantities.
- `Auctionator.API.v1.RegisterForDBUpdate` — trigger `FS_PRICES_CHANGED`.

If Auctionator is missing or its API changes, Prices reports "no price source" and only overrides work; nothing else breaks.

### 5.2 Profession side panel (docked to Blizzard's Professions frame)

- Selected recipe: predicted quality, skill vs threshold bar, concentration cost, cheapest reagents per reachable quality, **Apply** (fills reagent slots).
- Profit breakdown: reagent cost, expected sale (quality-weighted, after 5% AH cut), Multicraft/Resourcefulness/Ingenuity contributions, gold per concentration.
- Buttons: **Add to Queue** (quantity), **Craft Next** (one craft per click from the queue for this profession).
- Small profit label on rows in Blizzard's recipe list (separately toggleable; hook-based; disables itself on error).

### 5.3 Crafting Orders additions (Phase 2)

Extra columns (profit, score, risk flag), customer highlight/blocked warning, filter toggles, **Claim Best Order** button. All docked/added, never replacing Blizzard's list.

### 5.4 Tooltips

Item tooltip lines: cost to craft (best character), which characters can craft it, how many each character + warband bank holds.

## 6. Phase 1 — crafting math, profit, queue

### 6.1 Math

- **Skill and quality:** total skill = recipe base + reagent quality contribution + specialization bonuses + tools/gear; compared to recipe difficulty and quality thresholds → predicted quality and skill to next quality.
- **Concentration:** cost to reach a target quality from current skill; projected concentration over time from snapshot; gold per concentration point = (profit with concentration − profit without) ÷ concentration cost.
- **Reagent optimizer:** for each reachable target quality, the cheapest mix of reagent quality ranks that reaches it (Midnight reagents have 2 ranks — exhaustive / DP search is cheap). Evaluates finishing and optional reagents from GameData.
- **Bonus stats:** expected Multicraft extra yield, expected Resourcefulness reagent savings, expected Ingenuity concentration refund, using stat values from the game's operation info when available and from GameData + spec state otherwise.
- **Expected profit per craft** = Σ(quality outcome probability × sale price at that quality) × expected yield × 0.95 − reagent cost × (1 − expected resourcefulness saving).
- **Ground truth:** when the profession window is open, `GetCraftingOperationInfo` is authoritative for the current setup; Math is used for what-ifs and offline. Every open-window prediction is compared and mismatches logged to diagnostics.
- **Reference:** CraftSim (MIT-licensed, GitHub `derfloh205/CraftSim`) may be studied as a reference for formulas; code is written fresh and credited where formulas are derived from it.

### 6.2 Profit and prices

- Per-quality AH prices via Auctionator; vendor prices for vendor reagents; manual overrides win.
- Owned reagents costed at market price by default; setting to cost them at zero.
- Missing price → result shown with a "no price" flag and excluded from profit sorting (not treated as free).
- Price age shown everywhere a price is used.

### 6.3 Recipe scan

Ranks every known recipe on every character by profit and by gold/concentration. Runs in time-sliced chunks (coroutine, frame budget) to avoid stalls; re-runs on `FS_PRICES_CHANGED` or `FS_DATA_CHANGED` for affected recipes only.

### 6.4 Queue

- Add from side panel or Recipes tab (quantity, character, target quality, concentration on/off).
- Restock targets: "keep N of item across bags + bank + warband bank"; queue tops up the difference.
- Missing reagents = required − held on the crafting character − (optionally) warband bank.
- **Shopping List**: creates/updates an Auctionator shopping list "FabricationStation" with exact items and quantities.
- **Craft Next**: on click, applies the optimal reagent allocation and calls the craft once. If the needed profession window is not open on the right character, it shows which character/profession to open.
- Cooldown crafts can be queued and show their ready time.
- Limitation: no sale-rate data (TSM-only); restock is inventory-target based.

### 6.5 Minimal alt data (Phase 1 slice)

Per character: known recipes, skill, spec state, concentration snapshot, item counts. Collected whenever that character logs in and opens each profession once.

## 7. Phase 2 — orders, customers, ledger

- **Order scoring:** reagent cost you supply, commission after Blizzard's cut, reward values (knowledge, Moxie, reagents via Prices/GameData), reachable vs minimum quality, concentration needed → net profit, gold/concentration, score.
- **Risk flags:** no reagents + low tip, unreachable minimum quality, insufficient concentration, near expiry, blocked customer.
- **Filters** to hide flagged orders; **Claim Best Order** (one click per claim).
- **Orders snapshot** saved with timestamp for standalone viewing.
- **Customers:** captured on fulfilment (name-realm, item, quality, tip, date); notes, tags (VIP/blocked/custom), manual alt linking, search, export string; highlight in Blizzard's order list.
- **Ledger:** order commissions; AH sales parsed from "sold" mail; craft cost basis stored at craft time; weekly and per-recipe profit.
- **Commission benchmarks:** median/percentile tips from the player's own history per recipe and quality.
- **Alerts:** in-game sound + toast when a personal order arrives.

## 8. Phase 3 — alts and planning

- **Characters tab:** all fields in §5.1; data age per character.
- **Reagent location:** per-item totals by character and warband bank.
- **Weekly knowledge checklist:** per alt, per profession, from GameData knowledge sources (treasures, treatises, weekly quests, Darkmoon Faire, drops) and completion state.
- **Concentration scheduler:** ranks (character, recipe) pairs by gold/concentration; warns before any character's concentration caps; suggests what to spend it on.
- **Specialization advice:** next spec nodes ranked by profit gain on the player's profitable recipes.
- **Missing recipes:** unknown recipes per profession with source from GameData.

## 9. Phase 4 — public release and social

- Guild directory: who can craft what at what quality, via addon-to-addon sync (AceComm, chunked, throttled, out of instances) with native guild recipe query as fallback.
- Trade-chat scanner for crafting requests the player can fill.
- First-run setup wizard.
- CurseForge/Wago release.

## 9a. Phase 5 — pre-1.0 hardening

The work deferred from phase 4 that must settle before the first `v1.0.0` tag. Nothing here adds a feature area; it
changes how phase 4 data is stored, closes gaps the phase 4 review found, and finishes localization. Priority order:

1. **Compact stored guild profiles and a crafter index** (review M3, M5). Guildmates' profiles are saved in a compact
   form (the validated wire profile, each profession line's recipes packed into one string) instead of three
   per-recipe maps, with a forward SavedVariables migration that converts the old shape in place and never wipes
   data, and a per-guild cap on stored profiles that drops the least recently seen first. Lookups go through a
   `recipeID -> characters` index kept next to the item index and rebuilt in the same time-sliced ticks, so a tooltip
   no longer scans every stored profile. The sync wire format and `Protocol.VERSION` do not change.
2. **Hiding the setup guide is not skipping it.** Only Skip, the close button and finishing record a choice. When the
   guide is hidden any other way (the UI hidden with Alt+Z, a cinematic, Escape) it stays pending: it comes back with
   the UI, or at the next login. Guild sync stays held until a real choice, and the hold is still never permanent for
   a user who is not offered the guide.
3. **Typed search in the Guild tab.** A recipe name or a shift-clicked item link resolves to recipes, shows their
   guild crafters, and lists a recipe nobody is known to craft so "Ask guild" can ask the game about it (a click,
   through the native query's queue and gate).
4. **Setup guide text fits any language** (review M6): wrapped text boxes are sized from the measured text, and the
   window grows to fit; a test under an artificially long locale proves nothing is cut off.
5. **Whole-sentence localization.** Display text built by joining pieces (`"Income: " .. money`, plural endings,
   bracketed qualifiers) becomes one format-string key per sentence, area by area, with a checker that keeps it that
   way. English output does not change.
6. **Small deferred items:** the release gate also checks the `## Interface` line and the licence/notices files; long
   CHANGELOG and comment lines; the setup guide's duplicate profession row and greyed labels; a missing utility test.

Out of scope for phase 5: the guild privacy defaults (`share = true`, `shareAlts = "guild"`, the user's decision);
anything that needs the game client to verify (it becomes `P5-` lines in `docs/in-game-checklist.md`); releasing,
tagging or pushing; Classic; everything in §10.

## 9b. Phase 6 — polish and guild recipe dedup

The minors that phase 5 and the order-row work after it deferred, and one storage question. Nothing here adds a
feature area. Priority order:

1. **Polish.**
   - Guild directory and Guild tab: the search catalogue follows new guild data and newly learned recipes, an
     auto-selection survives a guild change, and a recipe whose profession is not known says so.
   - Setup guide: the step counter never sits under a button, the social headings grey out with their buttons, and a
     scan row that is cut off shows its full text on hover.
   - Order rows: every hover handler runs inside error isolation, a game call that fails on a row reads as "unknown",
     and the settings text describes the icons where they are now.
   - Localization: the checker also catches bracket and dash joins and one-line label tables. Duration letters,
     order and ledger types and the last joined labels become keys. Plural keys take `%d`. Ambiguous keys get
     translator context, and every area has a translated-locale test.
   - Docs: the CHANGELOG lists phase 5 and the order-row additions, and the README and CHANGELOG keep to 120 columns.
2. **Guild recipe-list dedup** (store a profession line's packed recipe string once per guild instead of once per
   character). It is built only if it saves at least about 20 % of the stored guild data on realistic data. The
   phase 6 plan measured 0–2 % for a realistic guild with the default quality sharing. It reached 39–77 % only when
   most characters know every recipe of a line with the same expected qualities. So it is not built in phase 6. A P6
   check counts the identical lines in a real SavedVariables file, and that count decides whether it comes back.

Out of scope for phase 6: the guild privacy defaults; the `Protocol.VERSION` and the wire format (unchanged); anything
that needs the game client to verify (it becomes `P6-` lines in `docs/in-game-checklist.md`); releasing, tagging or
pushing; the spec items listed as not built in the phase 6 plan's appendix, unless trivial; everything in §10.

## 9c. Phase 7 — competitive features

The features other retail crafting addons have that a seller needs most (`reports/Feature gaps 2026-11-01.md`; ids in
brackets). Every action stays a player click or key press (rule 3). In dependency order:

1. **Orders across characters** [C5, C1, C6]. Each character keeps its own last order board (a saved-data migration;
   alts with the same profession no longer overwrite each other). The Orders tab lists every character's orders in
   one list, with each board's age, expiry, sorting and filters. Patron rewards are priced: knowledge points at the
   player's gold value per point, Moxie and reagent rewards by value, any other reward at a value the player gives
   it, and a "costs too much" risk
   when an order costs more per knowledge point or Moxie than the player allows. Selected orders become one
   Auctionator shopping list of their missing reagents.
2. **Ready alerts** [V5]. Opt-in, in-game only: concentration full, Moxie over a threshold, a cooldown ready, and a
   taskbar flash (`FlashClientIcon`) on new orders that match the filters. A Refresh button on the order board asks
   for the board once per click; nothing refreshes on a timer.
3. **Sales and stock** [C12, C2]. The player's own auction posts, cancels, expiries and sales (own events and own
   mail; this is the player's own history, not the excluded TSM sale-rate data), a personal sale rate and last sale
   price per item in a Ledger view and in item tooltips. Restock targets get a minimum profit per craft, and count
   the player's own auction listings and mail as held.
4. **Craft log** [C11]. Every craft's real result (quality, Multicraft extra items, Resourcefulness returns,
   concentration spent) next to FabricationStation's and the game's prediction, per recipe over time, and an exporter
   that turns logged crafts and `/fs capture` records into the golden fixtures of §11.
5. **Better crafting choices** [C3, C4, C13]. A finishing and optional reagent optimizer (one slot at a time, or every
   combination when there are few) whose pick shows in the side panel and is crafted by Craft Next. Saved craft lists
   with rules (minimum profit, minimum quality, concentration off / single best / across recipes) queued with one
   click, and "Queue plan" for the Planner's concentration schedule. For reagents a character can craft: craft cost
   against buy price, the player's choice per reagent, and the sub-crafts queued ahead of the craft that needs them
   (at most 3 levels, never in a cycle).
6. **Getting reagents** [C14, C15]. A gathering plan per missing reagent (alts' bags and banks, mail, crafting it,
   vendor, auction house). At the bank, a button moves exactly what the queue still needs from the bank or warband
   bank into the bags, one move per click; at a merchant, a button buys the queue's vendor reagents, one click per
   batch. Nothing moves or buys when a window opens.
7. **Chat requests and key bindings** [V7, V8]. Chat requests are kept in a list across characters with reply status,
   the whisper history and auto-dismiss; replying fills the chat box and sends nothing. Key bindings for Craft Next,
   Claim Best Order, opening FabricationStation and replying to the latest request, each a key press that runs the
   same click handler as its button.

Out of scope for phase 7: automatic crafting, claiming, posting, buying or item moves; board auto-refresh on a timer;
TSM; Syndicator; notifications outside the game; anything that needs the game client to verify (it becomes `P7-` lines
in `docs/in-game-checklist.md`); releasing, tagging or pushing; everything in §10.

## 10. Out of scope

- Classic clients.
- Notifications outside the game.
- Any crafting, claiming, posting, or buying without a player click.
- Crafter reputation and community-wide commission data (would need an external service).
- TSM integration and sale-rate data.

## 11. Testing

- **Unit tests** with `busted` (Lua 5.1-compatible) outside the game. Math tested exhaustively; other modules tested against a WoW API stub layer.
- **Golden fixtures:** `/fs capture` stores the game's schematic, operation info, and predicted quality for the selected recipe; an export script turns captures into test fixtures. Math must reproduce the game's results on every fixture.
- **In-game self-check:** open-window predictions compared to the game; mismatches logged and surfaced on the Settings tab.
- **Lint:** `luacheck` with WoW globals config.
- **CI:** GitHub Actions runs luacheck + busted on every push.

## 12. Error handling

- Each module's event handlers and UI hooks run inside error isolation; a failing module disables itself, logs the error, shows a message, and the rest keep running.
- Blizzard-frame additions are individually toggleable.
- Saved data has a schema version with forward migrations; never wiped on upgrade.
- Performance: bag/bank events debounced; Math results cached per (recipe, character, reagent allocation, price version); recipe scan time-sliced.

## 13. Patch maintenance

- GameData rebuilt by an offline script from the game's data tables (as published by wago.tools DB2 exports), stamped with build number.
- Patch-day checklist: bump `## Interface`, rebuild GameData, run tests, capture fixtures for a few recipes per profession, check the mismatch log.
- Packaging via `.pkgmeta` (BigWigs packager) so public release is a configuration switch.

## 15. Risks and open questions

- **Math accuracy** is the largest risk of replacing CraftSim. Mitigated by golden fixtures, in-game self-check, and CraftSim as a formula reference.
- **GameData sourcing:** exact DB2 tables for spec node effects and reagent effects must be identified during Phase 1 planning.
- **Auctionator API names** and price-age availability must be verified against its source.
- **Mail parsing for AH sales** depends on mail subject/format; may need locale handling (English first).
- **Restricted-function behaviour** of `CraftRecipe` at runtime is unconfirmed; designed as click-only regardless.
